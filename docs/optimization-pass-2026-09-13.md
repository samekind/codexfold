## 实现范围

1. **批量原件回收**：同批次共用一次 pack doctor 和 fold doctor。持有对象存储操作锁及 pack lease，阻止 pack/fold 发布改变验证基础；不预先锁住全部 session。每份原件仍取得自己的写锁、完整物化、校验状态版本和原件身份，再按既有事务删除。
2. **删除前目标检查**：批量操作只读取目标 session 的状态和 manifest，避免并行任务互相撞上对方的中间发布状态。单独手动 `retire-native` 保持原来完整验证路径。整库空间统计从每份原件两次降为每批两次。
3. **可调并发与让路**：`fs enroll reclaim --apply --workers 1..16`；`fs enroll apply --reclaim-workers` 也可指定。常驻服务空闲时最多 4 路，有最近两秒内的实际读写时，新派发工作降为单路；已开始的安全事务先完成。忙时松散对象回收也限制单路，并降低后台子进程调度优先级。此策略不等于整个 daemon 的硬 CPU 限额。
4. **真实进度**：一开始就把预计原件回收项、松散对象清理及 GC 纳入总工作量；清理阶段按实际候选调整，逐项报告进展和真实已纳管数。失败／暂缓不提前报完成。没有重做 Swift UI。
5. **流式读取**：每个顺序对象流只保留当前解压块，避免 32/128 KiB 小读取反复解压同一大块；关闭即释放。doctor 复用读取缓冲区，并在最多 256 个对象的窗口内按 pack/偏移排序，不建立全库对象内存表。
6. **增量 pack**：CLI 默认 `--incremental=true`。新一代索引只指向自己的目录，未变化的不可变 pack 文件用硬链接复用，不复制旧载荷。旧代目录删除后，新代仍可读。出现已删除对象、旧代已有 16 个或更多 pack 文件、或块尺寸不兼容时，自动整理；`--incremental=false` 强制整理。整理时仍可直接复制已验证的压缩块，避免重新编码。发布前完整数据校验保留。
7. **空间预算**：增量路径按新增／需要重写的对象及索引、恢复归档的保守上限估算，不再把共享旧载荷全部算成新增磁盘占用。仍保留磁盘保留线，不用猜测压缩率放松预算。
8. **状态观察**：按需加载只检查目标；后台只读观察缓存已验证且身份、ctime、mtime、大小未变化的主状态／catalog／checkpoint，最多十秒。最终发布与删除检查不使用该缓存。活跃初始化租约与已弃置 staging 分开识别；原件退休检查先拿目标写锁并重读状态，避免拿旧状态误判新证明。

这些改动没有引入新的存储格式、独立数据库队列、无限内存缓存、GPU 或模型请求。
候选发现仍每批核对真实状态，完整安全验证仍与库规模有关；不能声称所有操作已经是纯 O(新增数据)。

## 实测

所有删除测试都在临时 store；生产源文件只读。测试结束后临时数据由测试框架清理。

只读选取十个 1–16 MiB 的真实归档 session，总计 52,682,764 字节。旧版基线为当时生产 `559936d2…`。

### 同一真实 session 的十份副本

总计 99,959,660 字节：旧版 8.087 秒；新版 1/4/8 路分别 3.136 / 2.204 / 2.191 秒。每组原件与松散对象归零，全部恢复一致。4 路是默认空闲上限，而不是认定线程越多越好。

### 状态观察

对生产 526 个 session 的元数据做只读比较，每组十次：未缓存约 89.237 ms/轮；缓存约 45.945 ms/轮。没有改生产状态，也不将这两个数字当作整个 daemon 的 CPU 降幅。

### 完整双批次与回退兼容

真实 fold → pack → 创建托管状态 → 原件回收 → 松散对象回收 → 旧代 GC → 全量读回：两轮均通过。第二份相同输入新增对象存储为零，旧 pack 被回收，原件快照和松散对象均归零。当前生产旧二进制也能完整恢复新版增量 pack 中的内容。

## 回归与边界

- 批量证明只建立一次、对象变更锁在批次期间有效、manifest 改变及关闭后的 batch 被拒绝。
- 并发上限、前台忙时降为单路、各任务结束后才释放共同资源。
- 顺序流不重复解压当前块，损坏压缩源不会被发布成新 CURRENT。
- 增量数据共享物理文件；旧代 GC 后读回不变；删除对象时不继续链接旧载荷。
- 状态主文件、checkpoint 的修改和同大小／恢复 mtime 的改写均使观察缓存失效。
- 活跃 staging 不误报弃置；租约释放后的弃置 staging 仍被报告。
- 延续原有写入冲突、取消、损坏 pack、原件身份变化、事务恢复测试。

复现入口：`TestNativeRetirementRealBatchComparison`、`TestInstalledFoldAndCompleteCleanup`、`TestStateInspectionCacheComparison`，以及新增 `NativeRetirementBatch`、`IncrementalBuild`、`SequentialObjectStream`、`StateInspectionCache` 测试。

生产自动折叠开关属于用户设置，更新不擅自打开它。升级继续只换 Go 程序，不关闭 Codex，并保留独立恢复脚本和旧二进制。
