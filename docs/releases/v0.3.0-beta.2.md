# CodexFold v0.3.0-beta.2

This prerelease completes the Pack V3 and Pack-only recovery path for the
transparent filesystem preview. Folded objects can now be retired from the
loose object tree after complete pack verification, while managed sessions,
current Codex clients, forks, and native rollback retain exact behavior.

## Highlights

- Bounded-memory Pack V3 files and indexes replace object-per-file reads on the
  transparent path.
- `pack retire-loose` verifies every packed object and manifest before deleting
  eligible loose objects.
- `fs retire-native` removes a canonical retained snapshot only after pack-only
  recovery, writer exclusion, full materialization, and durable proof checks.
- Filesystem health and automatic-enrollment gates understand Pack-only stores
  and fail closed when an authoritative current pack is damaged.
- Native FSKit service installation rejects Unix socket paths macOS cannot
  bind.

## macOS Canary Evidence

The isolated Canary used signed Apple-native FSKit build 102, source metadata
build 103, current PATH CLI `0.144.3`, and Desktop `26.721.31836+5828`.

- 63 of 63 objects and 4 of 4 manifests verified before all loose objects were
  retired.
- Service restart preserved exact bytes for all three managed sessions.
- Real CLI and Desktop turns read complete prior history, inspected a real Go
  project, and completed `go test ./...`.
- An official Desktop fork produced an independently writable native child;
  child-only and parent-only markers did not cross branches.
- Pack-only canonical rollback produced an exact ordinary native JSONL, and a
  subsequent real CLI native resume succeeded.
- Go daemon, supervisor, Host, and FSKit extension crash recovery preserved
  exact SHA-256 values.
- A 256 MiB managed performance run passed cold and warm ratio gates at `3.009`
  and `1.024`, with `F_NOCACHE` active and aggregate service RSS below 256 MiB.

## Install the CLI

```bash
go install github.com/samekind/codexfold/cmd/codexfold@v0.3.0-beta.2
codexfold --version
```

Release archives contain the default storage-oriented CLI for macOS, Linux,
and Windows on `amd64` and `arm64`, plus `checksums.txt`. The locally validated
FSKit App is not attached because it uses an Apple Development identity rather
than a generally distributable, notarized Developer ID identity.

## Readiness Boundary

The filesystem remains opt-in and reports `fs-engine-preview`. The isolated
macOS candidate has completed executable Pack-only, current-client, restart,
fork, rollback, process-recovery, and performance gates. General production
promotion still requires the incident-free observation period and a controlled
in-flight host power-interruption test. Linux still lacks a real Codex client
gate, and Windows still lacks a real WinFsp runtime gate.
